```rationale
The current round-robin batch_assignment ignores setup/processing asymmetries and machine-specific loads, while the permutation sorts purely by setup (ignoring processing times and reentrancy constraints). This explains the wide score spread (0.529-0.771) and the 0.275 gap to best-known. Highest-impact fix is a solver_lib helper that computes a weighted key (setup+processing) for permutation + a simple load-balancing batch re-assignment; generalize via metadata (n_jobs, n_machines) rather than task_id literals. Keep helpers small, self-contained, and pure-Python so the sandbox solver can call them reliably.
```

```solver_lib:weighted_permutation
def weighted_permutation(jobs: list, setup_times: list, processing_times: list) -> list:
    """Return job permutation sorted by weighted key (setup dominant, processing secondary).

    Args:
        jobs: list of job indices (0..n_jobs-1)
        setup_times: list of setup times for each job
        processing_times: list of total processing times for each job

    Returns:
        list of job indices in optimal order for the solver
    """
    def key(i):
        return setup_times[i] * 10 + processing_times[i] / 100
    return sorted(range(len(jobs)), key=key, reverse=True)
```

```solver_lib:batch_assignment
def batch_assignment(n_jobs: int, n_machines: int, processing_times: list) -> list:
    """Return batch_assignment that balances cumulative machine loads.

    Args:
        n_jobs: number of jobs
        n_machines: number of machines
        processing_times: list of total processing times per job

    Returns:
        list of machine ids (1-based) for each job
    """
    machine_loads = [0.0] * n_machines
    assignment = [0] * n_jobs
    for i in range(n_jobs):
        machine = min(range(n_machines), key=lambda m: machine_loads[m])
        assignment[i] = machine + 1
        machine_loads[machine] += processing_times[i]
    return assignment
```
