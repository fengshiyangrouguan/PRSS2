```rationale
The solver's inline DP for makespan has two fatal indexing bugs that trigger the reported "list index out of range" on every test case (including small n): (1) the inner loop starts at k=0 so C[j][k-1] dereferences a negative index, and (2) it reads C[n][m] but the matrix only has columns 0..m-1. Brute-force permutation search is also doomed for n>10-12 because of combinatorial explosion, but the immediate failure is the crash, which is why score=0.0. The largest headroom is in this task (+0.794 gap), so I will not touch other tasks. I supply a single, self-contained, correctly-bounded helper that follows the classic O(nm) DP for flow-shop makespan; the solver can call it directly after the pre_process hint. This is small, auditable, uses only stdlib, and will let the existing solver code run without rewriting the DP logic it cannot yet produce reliably.
```

```solver_lib:calculate_makespan
def calculate_makespan(matrix: list[list[int]], perm: tuple[int, ...]) -> int:
    """Compute makespan for a flow-shop schedule.

    Args:
        matrix: 2D list where matrix[j][k] is processing time of job j on machine k (0-based)
        perm: tuple of job indices in the sequence order (0-based)

    Returns:
        int: makespan (completion time of the last job on the last machine)
    """
    n = len(perm)
    m = len(matrix[0]) if matrix else 0
    C = [[0] * m for _ in range(n + 1)]
    for j in range(1, n + 1):
        for k in range(m):
            if k == 0:
                C[j][k] = C[j - 1][k] + matrix[perm[j - 1]][k]
            elif j == 1:
                C[j][k] = C[j][k - 1] + matrix[perm[j - 1]][k]
            else:
                C[j][k] = max(C[j - 1][k], C[j][k - 1]) + matrix[perm[j - 1]][k]
    return C[n][m - 1]
```
