## 1. 从 Stage1 开始微调的结果（legacy 构造）

**构造**：llama-7b-no（Stage1 对话 LoRA foundation）起点 + resize 32004 + **冻结随机 COMP/SUM 词元嵌入** + fp16。此构造下 COMP/SUM 的压缩语义从未被训练（Stage1 不含压缩任务）。

**150 步（五桶口径，turn-14 子集）**：

| 臂 | turn_3 PPL | turn_14 PPL |
|---|---|---|
| legacy ours | 159.2（loss 4.98） | 9.02 |
| legacy task-only | 171.9（loss 5.05） | 9.04 |

**200 步（pooled 五桶口径）**：cond 臂 turn_14 PPL 6.36（loss 1.757）、task 臂 6.37——仍远差于官方 merge 的 5.48（5L 口径 L13）。

**对照（官方 merge 模型在同样评估上的表现）**：turn_14 5.48-5.56 PPL（5L clean 口径 L13 / foundation 五桶口径）。

**结论**：从 Stage1 起点微调，压缩能力从头学起，200 步内完全无法逼近官方 merge 水平；冻结随机 COMP/SUM 嵌入使压缩接口从第一步起就与官方语义断裂。审阅第七轮对此的定论（"关键 compression embedding 一直未训练"）成立。

## 3. 结论汇总

### 3.1 官方宿主继承（R7）是必要前提

- 从 Stage1 起点微调（legacy）：200 步后 turn-14 仍差官方 merge 约 1.2-1.6 PPL，短对话 PPL 高达 160+——压缩能力从未建立
- 从官方 merge 起点（R7/R8）：step0 与官方逐位一致（gate d=0），训练在官方水平上起步，200 步内全曲线进入官方 ±2% 带内
- **"站在官方两阶段协议的肩膀上"是唯一可行的路径**（R7 gate 证明）

### 3.2 R8 协议修复的收益：主要归因于数据协议，而非 RPBE

- 深度分层 + 官方宿主下，val 深度曲线**全线改善**（R7 的 L1 恶化 +0.021 翻转为 R8 的 −0.024；L13 改善从 −0.005 放大到 −0.057）
- **关键归因证据**：task-only 臂（无 RPBE 信号）与 ours 臂 s50-s200 完全同步（≤0.003）——改善来自**深度分层训练暴露（50% turn-14）+ LoRA 微调**，两臂共享
- 深度桶、4×32 ensemble、OAS 收缩的作用是**让统计与训练更稳**（J_real−shuffled 同口径 +0.9、α 温和、分支一致），它们本身不产生 val 增益，但消除了旧协议下的口径问题

### 3.3 RPBE 在官方预算内的 null result：瓶颈不在 merge 算子

- 训练信号真实存在且被优化（J_ens 增长、J 显著高于对话级 shuffle 基线）→ Γ 确实学到了东西（U 范数 5.5e-3）
- 但 300 步内未转化为 held-out 收益：两臂配对差异在噪声带内
- **建议论文措辞**："在官方 300 步微调预算与匹配初始化下，未来充分性信号在训练中被有效优化，但未转化为 held-out 深度利用的额外增益——两臂配对差异落在统计噪声内。这表明在 DailyDialog 官方算术平均压缩协议下，**压缩瓶颈不在 merge 算子本身**：数据协议（深度分层暴露）带来的收益显著，merge 规则的可优化空间在本预算内已饱和。"
- "撞到压缩能力上限"需要加限定词（"本协议/预算内"）；正在进行的 seed1 + r_eff=0.3（λ=0.0669，3× 信号强度）是"加大力度仍无增益"的验证点

### 3.4 次要发现

- **L8 漂移**：ours 的 L8 从 s100 最优（−0.015）单调恶化到 s300（+0.010），但 task-only **同样漂移**（s150 回落同步）→ 归因 LoRA/数据流，非 Γ/RPBE
- **选模时点分层错开**：深层最优 s200、浅层最优 s300——按深度利用主口径推荐 s200
