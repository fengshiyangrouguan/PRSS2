## 第 0 章 前置知识速成

在逐条讲解前,先花 3 分钟建立 8 个基础概念。每条后面都会用到。

### 0.1 状态 = 一串数字(向量)

模型里每个"东西"都用一串数字表示,比如 TGN 里每个用户节点的状态是 172 个数字。数字串越长,"表达能力"越强,但计算越贵。**"压缩"就是把 256 个数字压回 172 个数字,同时尽量保住有用的信息。**

### 0.2 投影 = 选方向

压缩通过一个矩阵 R(172 行 × 256 列)完成:`z = R·h`。直觉:**h 是 256 维仓库里的货物,R 是"取货清单",z 是取出来的 172 件货**。R 的每一行代表一个"取货方向"。

### 0.3 梯度 = 成绩单

神经网络训练靠"试错":先算一个损失(错误程度),然后反推"每个参数该怎么微调才能让错误变小"——这个反推就是**反向传播**,每个参数拿到的"该怎么调"就是**梯度**。训练 = 反复按成绩单微调。

### 0.4 Gram 矩阵 = 需求使用频率表

B 是"未来需求预测员"输出的读取向量(第 0.3 条里的"取货方向"的预报)。把很多个 B 收集起来算 `G = 平均(BᵀB)`,得到一个 256×256 的表:**第 i 行第 j 列的数字 ≈ "第 i 维和第 j 维被未来需求捆绑使用的频率"**。这张表就是后面选方向的依据。

### 0.5 特征分解 / SVD = 找主方向

对 Gram 这张表做**特征分解**(EVD,也叫 eigh):它会吐出 256 个"特征方向",每个方向带一个"特征值"(重要程度)。**取特征值最大的前 172 个方向,就是"在只能取 172 件货的前提下,总价值最大"的取法**——这是数学上可证明的最优解,不是拍脑袋。SVD(奇异值分解)是同一件事的另一套说法:把很多 B 竖着堆成大矩阵,取它的"右奇异方向"= 取 Gram 的特征方向。术语"谱"= 所有特征值的分布;"能量"= 特征值之和;"energy@k" = 前 k 个特征值之和占总和的比例。

### 0.6 detach = "参考可以,追责免谈"

`detach()` 的意思是:计算时照常用这个数,但**不允许梯度穿过去追责它**。用于两种情况:① 裁判信息(监控用,不许反向影响选手);② R 这种"由 SVD 决定、不靠梯度学习"的量。

### 0.7 训练 / 验证 / 测试 + 数据泄漏

- **训练集** = 练习题;模型天天做,并根据错误更新参数。
- **验证集** = 模拟考;不更新参数,只用来决定"练到第几轮最好"并选最佳模型(叫 early stopping / 模型选择)。
- **测试集** = 期末考;只在最后用一次,分数写进论文。
- **数据泄漏** = 期末考题提前流入训练决策(比如拿测试集成绩决定什么时候停)。泄漏会让分数虚高,且无法察觉。

### 0.8 随机种子 / 消融 / 基线

- **种子(seed)** = 随机数发生器的起始点。换种子 = 换一套初始参数和采样顺序。论文要求跑多个种子,报"均值 ± 标准差",因为单次结果可能是运气。
- **消融(ablation)** = 把方法拆成零件,逐件拆掉看分数掉多少——用来证明"是哪个零件在起作用"。
- **基线(baseline)** = 对照组。没有对照组,"分数高"无法归因。

### A1. 谱更新用"阻尼小步",而不是一次到位部署 SVD 解

**规格要求**(§12 伪代码 F 段):每 200 步对 Gram 做一次特征分解,取 top-k 方向,对齐后**直接把新 R 部署上线**:

```python
if step % spectral_update_interval == 0:
    eigvals, eigvecs = eigh(G_ema[tau])
    V_top = eigvecs[:, -k:]          # d x k
    R_new = V_top.T                  # k x d
    R_new = procrustes_align(R_new, R[tau])   # 对齐坐标系
    R[tau] = stopgrad(R_new)         # 直接换上
```

**代码现实**(`PRSS-method/prss/spectral.py`,`update()` 函数):默认 `spectral_step_size=0.25`,只在 `spectral_step_size=1` 时执行上面的"直接换上"。默认路径是**带回溯的 Grassmann 爬山**:

```python
# 目标仍然是 SVD 精确解,但每次只允许走一小步
direction = old64 @ g @ (eye_d - old_p)     # 在 Grassmann 上的"上坡方向"
alpha = self.spectral_step_size             # 步长 0.25
while alpha >= 1e-4:
    cand = row_orthonormalize((old64 + alpha * direction).to(old.dtype))
    score = ...  # 算新 R 捕获的需求能量
    if score > before + 1e-12:              # 能量必须上升才接受
        proposal = cand; accepted = float(alpha); break
    alpha *= 0.5                            # 否则步长减半重试
# 若完全爬不动(Grassmann 梯度为零),退而求其次:朝 SVD 目标插值一小步
```

**白话讲解**:想象 R 是货架布局,每 200 步拿到一张新的"需求地图"。理论说"直接按新地图重排货架";实现说"每次只挪 25%,而且先试一步——如果新布局的总需求反而下降了,就退回半步再试"。像开车打方向盘:理论是瞬间打满,实现是小步微调防翻车。

术语:**信任域(trust region)** = 每次允许的最大步幅;"回溯(backtracking)" = 步子太大就减半重试;"Grassmann 流形" = 所有 k 维子空间构成的空间(爬的是"方向集合"的山,不是坐标的山)。

**为什么这么改**:HOTFIX_V4 记录了血泪史——v4 版就是按规格"一次到位"部署,结果训练震荡直至失败(那次运行的目录还留在 `outputs/.../prss_matched_failed_*`)。原因:R 决定父节点收到的坐标 z,**坐标系统突然整体更换**,父聚合器与解码器面对的输入分布剧变,梯度流不稳定。

**影响**:运行时的 R **一般不是当前 Gram 的解析最优解**——最终快照显示 R 只覆盖当前 Gram 能量的 98.8%(层 1)/ 97.6%(层 2),留了缺口。论文如果写"解析最优",必须限定为"SVD 目标本身、以及 step_size=1 的情形";同时建议补一个 `spectral_step_size=1` 的对照实验,量化阻尼的代价。

### A2. 谱尾损失 L_spec 有一个"激活闸门"

**规格要求**(§9/§12):训练总损失含 L_spec = ‖B(I−RᵀR)‖²/(‖B‖²+ε),其中 R 来自最近一次 SVD 并 detach。规格没提"R 还是出厂默认时怎么办"。

**代码现实**(`prss/spectral.py`):

```python
def _has_deployed_data_driven_quotient(self) -> bool:
    # 检查 R 是否已经离开 [I,0] 出厂初始化(按元素比较,阈值 1e-7)
    init = torch.zeros_like(self.R); init[:, :self.host_dim] = torch.eye(...)
    return bool((self.R.detach() - init).abs().max().item() > 1e-7)

def spectral_loss(self, B):
    if not self._has_deployed_data_driven_quotient():
        return B.sum() * 0.0        # 闸门关闭:L_spec = 0(但保持计算图连通)
    # ... 闸门打开后才是真正的谱尾损失
```

**白话讲解**:L_spec 的任务是"逼需求预测员把注意力集中到货架 R 上"。但在第一次 SVD 之前,R 还是出厂默认(`[I,0]` = "前 172 维原样保留、新增 84 维扔掉",数值上等于原版 TGN)。拿出厂默认当"优秀布局"去惩罚预测员,等于逼他按错误标准工作。所以实现加了一道闸:**SVD 真正改变了 R 之后,L_spec 才生效**。HOTFIX_V5 还发现一个边界:就算算了 SVD,如果信任域一步都没接受(R 纹丝不动),闸门也必须保持关闭。

**为什么这么改**:防"用任意初始位置当正则化目标"。**影响**:本运行中 R 很快就移动了,闸门只影响训练最初期,对最终分数影响很小。

### A3. L_spec 的分母被"冻结"并设了下限

**规格要求**(§9):`L_spec = ‖B(I−P_R)‖²_F / (‖B‖²_F + ε)`——分子分母都随 B 变。

**代码现实**(`prss/spectral.py`,`spectral_loss()`):

```python
num = residual.square().sum(dim=(-1, -2))       # 分子:照常参与梯度
den = B.detach().square().sum(...).clamp_min(1e-4)   # 分母:detach 冻结 + 下限 1e-4
return (num / den).mean()
```

**白话讲解**:这是个比值函数。数学上 `1/x` 在 x 接近 0 时斜率无穷大——翻译成人话:**当预测员 B 的输出接近全零时(标签极稀疏时它很容易缩水),这个比值的梯度会爆炸**,训练就崩了。实现的处理:分母的数值照算,但**不让梯度追究分母**(detach),再给分母垫一个地板(最小 1e-4)。代码注释明确声明:这只改变 B≈0 退化点的优化条件,**不进入 Gram、不影响 SVD 解**。

**影响**:本运行中 B 的范数健康(≈7.4),此项几乎无感。纯数值稳定性补丁。

### A4. Gram 的初始值:零 + 首次直接赋值,而非规格的"eps·I"

**规格要求**(§12 伪代码开头):`initialize G_ema_tau = eps * I`——从"对角线撒了一点噪声(1e-8)的单位矩阵"起步。

**代码现实**(`prss/spectral.py`):

```python
self.register_buffer("G", torch.zeros(self.candidate_dim, self.candidate_dim))  # 零初始化
# accumulate() 里:
if int(self.reader_gram_updates_t.item()) == 0:
    self.G.copy_(gram)        # 第一次:直接赋值,不混合
else:
    self.G.mul_(1.0 - self.gram_ema).add_(gram, alpha=self.gram_ema)  # 之后:EMA 混合
```

**白话讲解**:先解释 **EMA(指数滑动平均)**:每次新数据进来,不直接替换统计表,而是"新表 = 95% 旧表 + 5% 新数据表"——像长期记账,新账页只占 5% 权重,统计平稳不易被单批数据带飞。规格想把初始账本设成"每个方向平等地有一点点"的 eps·I;实现选择"空账本,第一笔直接记入"。差别在于早期几批数据:eps·I 会给没见过的方向一个平等的微小先验(避免早期谱出现绝对零),但也会轻微污染早期谱;零初始化则让谱完全由数据决定。

**影响**:EMA 很快就会把初始值洗掉,长期无差别。归类 A 只是因为它偏离了伪代码。

### A5. ridge 垫片 1e-8 vs 规格建议 1e-5

**规格要求**(§23):`ridge_eps: 1.0e-5`。**代码现实**(`prss/spectral.py`):构造函数默认 `eps=1e-8`,`update()` 里 `g = g + eps * eye`。

**白话讲解**:特征分解前,给 Gram 对角线加一个小常数(术语:**ridge / jitter / 对角加载**)。作用是保证矩阵"良态"——防止分解出负数或无穷的特征值,像给摇摇欲坠的梯子加垫片。1e-5 和 1e-8 都是"很小",本运行中不改变任何结论。

**影响**:无。建议统一数值,纯洁癖问题。

### A6. 接口类型 τ 按"层"分,而不是按"关系类型+角色"

**规格要求**(§15):接口类型建议 τ=(relation type, message/update role),例如 `src_to_dst/关系r`、`dst_to_src/关系r`;若数据只有单一关系,**先全局共享一个 R**。

**代码现实**(`prss/core.py`):每层一个 `SpectralQuotient`,名字就叫 `tgn_layer_{l}`;同层内"源节点递归"和"邻居递归"共用同一个 R(`prss/tgn_adapter.py` 的 `_compute` 对两类子调用不做区分)。

**白话讲解**:"接口类型"= 哪些位置**共享同一个货架布局 R**。共享得越多,每个 R 能统计的样本越多、越稳,但也越粗糙。规格的理想是按"关系种类 × 消息角色"细分;但 Wikipedia 数据只有一种边关系,实现退而求其次按"递归层"分:第 1 层的所有节点共用一个 R₁,第 2 层共用一个 R₂。单关系数据下这完全符合规格"先全局共享"的精神。

**影响**:不影响分数;论文需明确写出"τ = 递归层"这一定义。

### A7. 层 0(叶子层)被完全排除在 reader/Gram 之外

**规格要求**(§0.1):若某接口 d=k(没有压缩空间),PRSS"只能学习预测相关的坐标/子空间重组,不能宣称该处发生了维度压缩"。

**代码现实**(`prss/core.py`):层 0 的候选宽度 = 宿主宽度(172),**不为层 0 建 reader、unrestricted reader 或候选构建器**;`METHOD.md` §1 明确写了原因。

**白话讲解**:层 0 = 原料层(原始节点特征 + memory),宽度本来就是 172,**没有压缩可做**。规格说理论上还能学个"坐标重摆"(把 172 维摆成更顺手的姿势);实现选择完全跳过——反正不改变前向数值,省事且零风险。

**影响**:合规,不影响分数。

### A8. 每层配一套独立 reader,而非规格的"共享主干+类型小头"

**规格要求**(§7):推荐"一个共享 context 编码器 + 关系类型嵌入 + 小型类型条件矩阵头"。

**代码现实**(`prss/core.py`):

```python
for l in range(self.n_layers + 1):
    if l > 0:
        self.readers[str(l)] = ConditionalMatrixReader(context_dim, d, hidden_dim=reader_hidden)
        # ↑ 每层一个独立的小网络,不是共享主干
```

**白话讲解**:规格设想"一个总部培训中心 + 各门店的小招牌"(共享主干、省参数);实现是"每层一个独立门店"(每层一套参数)。后者的好处是不同层的"未来需求模式"完全独立;代价是参数更多、每层可用的训练样本不变。属于实现变体,没有对错。

**影响**:改变训练动力学;更多容量通常无害(甚至略有利),但参数效率低于规格设想。

### A9. 兄弟摘要用"平均值"

**规格要求**(§6):子节点上下文包含 `Agg_{s∈siblings(v)} t̃ilde h_s`——**Agg 是什么聚合算子,规格没规定**。

**代码现实**(`prss/outside.py`,`sibling_summary()`):

```python
for sid in parent.children:
    if sid == excluded_child: continue
    projected.append(self.sibling_proj[str(s.layer)](s.candidate.detach()))
if not projected:
    return torch.zeros(...)          # 没有兄弟 → 零向量
return torch.stack(projected, dim=0).mean(dim=0)   # 平均
```

**白话讲解**:节点的"外部上下文"要告诉它:"你旁边发生了什么?"最朴素的方式是**把兄弟们的摘要平均一下**(也可以用最大值、注意力加权等)。注意 `.detach()`:兄弟只提供信息,不允许梯度追责兄弟——符合规格"detach 版本"的要求。

**影响**:训练期 teacher 的细节选择,方向性影响很小。

### A10. "无限制读者"(裁判)被完全隔离:detach 输入 + 独立优化器

**规格要求**(§21.1):必须对比"结构化矩阵读者 B·h"与"无限制 MLP 读者 MLP(h,C)"——若后者明显更好,说明非线性 lift 不足,不能盲信 SVD。

**代码现实**:
- `prss/reader.py` 的 `UnrestrictedReader`(MLP);
- `prss/auxiliary.py`:`ulogit = prss.unrestricted[str(occ.layer)](c.detach().unsqueeze(0), cand.detach())`——输入双双 detach;
- `experiments/train_supervised_prss_switch.py`:给 unrestricted 参数单独建一个 Adam 优化器,与主优化器分开。

**白话讲解**:无限制读者是**裁判**:它用"随便怎么读"的方式预测标签,用来衡量"我们的线性读取假设是不是太弱"。它必须完全隔离:输入 detach = 它的预测**不允许反向影响主表示**(选手);独立优化器 = 它的学习不占用主优化器的步数。这样它才是一个干净的标尺。

**影响**:对最终分数零影响(监控专用)——但它是规格 §21.1 要求的诊断,现在**只做了训练集上的对比**(警告阈值 0.25),还没有系统性地报告"结构化 vs 无限制"的最终差距,这点见 C 类相关条目。

### A11. 官方锚点保留了"拿测试集当验证集"的历史协议怪癖

**规格/文档出处**:`OFFICIAL_PARITY.md` §1——"Its historical quirks are preserved rather than silently repaired."

**代码现实**:官方 `train_supervised.py` 以 `use_validation=False` 运行;上游 `get_data_node_classification` 在该模式下把 **val 和 test 设成同一份数据**(最后的 15%)。日志证据(`outputs/.../logs/gpu0_official.log`):每个 epoch 打印的 "val auc" 实为 **test** auc,early stopping 也盯着 test 成绩。

**白话讲解**:官方老脚本把"期末考卷"同时当"随堂练习卷"发:模型每轮对着考卷练,什么时候停也按考卷成绩决定。**这就是数据泄漏**(第 0.7 条)。所以 0.8933 这个锚点数字偏高,它存在的意义只是证明"任务和权重可复现",**不参与方法对比**;干净的对照是 matched 协议下的 vanilla 0.8855(有独立验证集)。

**影响**:只影响参考锚点的解读,不碰 PRSS 分数本身。

### B1. 训练期只跟踪每批 8 个根节点,且**正样本优先** ★最重要

**代码现实**(`experiments/train_supervised_prss_switch.py`,`select_trace_rows()`):

```python
def select_trace_rows(labels, max_roots, batch_index, seed):
    pos = np.flatnonzero(labels > 0.5).tolist()
    neg = np.flatnonzero(labels <= 0.5).tolist()
    chosen = pos[:max_roots]               # 1. 先把 batch 里的正样本全挑上(最多 8 个)
    remain = max_roots - len(chosen)
    if remain > 0 and neg:                 # 2. 不够 8 个,再确定性补负样本
        rng = np.random.RandomState(seed + 104729 * (batch_index + 1))
        chosen.extend(rng.choice(neg, size=remain, replace=False).tolist())
    return sorted(chosen)
```

后续链路:只有被选中的行,适配器才构建 trace 计算树(`tgn_adapter.py`),`build_auxiliary` 才产生 B(C),**Gram 只从这些 B 累积**(训练器第 658–662 行)。

规格伪代码假设"整批样本都过一遍训练期辅助管线"。但每棵树有 n_degree=10、2 层 → 最多约 111 个节点,整批(100 行)都跟踪会非常贵。实现**每批只跟踪 8 行**,而且**优先挑正样本**。

为什么优先正样本?数据极稀疏:每批 100 行里平均只有 0.14 个正样本。如果不优先,reader 几乎永远只见负样本,学不到"什么方向能预测出正样本"——那整个方法就废了。**但这个补救带来了两个代价:**

1. **reader 的监督分布与真实流量完全不同**(正负比例被大幅改写)——相当于社会调查只蹲富人区;
2. **Gram 的估计只来自这 8 行的 occurrence**,样本量小且成分有偏——而 R 直接由 Gram 决定。

**为什么没有文档**:策略写在 `select_trace_rows` 里,但 `METHOD.md`/`MONITORING.md` 都没说明这个采样设计。

**影响**:这是**方向未知、不受控地刻进 0.9001 的因素**。正根过采样可能恰好帮助了稀疏正例(好事),也可能系统性带偏 reader 与 Gram(坏事)。**建议**:① 文档化策略;② 消融 `--trace-roots`(8 vs 16 vs 全批);③ 把正根/负根的响应损失与 B 范数分开报告;④ 与持有者确认这是否算"有偏监督"。

### B2. 整棵树的所有节点,都用**根节点的标签**来监督

**代码现实**(`prss/auxiliary.py`):每个被跟踪的根对应一个标签,该根整棵树的所有 occurrence 都用这同一个标签算 BCE:

```python
label = row_to_label[int(top_row)]      # 根的标签
...
for oid in order:                        # 遍历整棵树的所有节点
    ...
    y = label.view(1)                    # 同一个 y
    slogit = prss.readers[str(occ.layer)].logits(B, b, cand)
    r_by_layer[...].append(F.binary_cross_entropy_with_logits(slogit, y))
```

**白话讲解**:一棵计算树的最终任务是根节点的标签(如"这个用户此刻是否被禁言")。中间每个节点也学"读我自己 + 我的上层未来,预测**根**标签"。这符合理论:子树的价值本来就由"根的最终预测"定义(规格 §2 的 Y 就是任务标签)。但它需要**在论文里写清楚**——否则审稿人会问"中间节点的标签从哪来?"。

**影响**:语义上合规;属"必须声明"而非"必须修改"。

### B3. 续跑(resume)不清理旧告警日志,最终报告混入历史告警

**代码现实**(`prss/monitoring.py` + 训练器):`MonitorWriter(reset_files=not bool(args.resume_from))`——续跑时 alerts.jsonl 不重置;`finalize()` 统计的是**文件里所有行**。证据:最终 `prss_matched/monitor/monitor_summary.json` 显示 `error_alerts=2`,但那 2 条是 v7 修复**之前**的假阳性(读者矩阵有限性误报),本次运行实际没有触发任何硬错误,状态为 complete。

**白话讲解**:新体检报告把归档前的旧病历也算进去了——"本次健康,但历史上有过 2 次误诊"。数字本身没错,口径会误导读者。

**影响**:只影响报告解读,不影响分数。建议把"历史遗留告警"与"本次运行告警"分开统计。

### B4. 只有 seed 0 一次运行,而且最佳模型出现在第 0 轮 ★

**证据**(`outputs/.../seed_0_l2/prss_matched/summary.json`):`best_epoch=0`;vanilla 的 best_epoch 是 6。

**白话讲解**:两点问题:
1. **单种子**:0.9001 是一次抽签的结果。换种子分数会动——可能更高也可能更低。论文标准是跑 3–5 个种子,报"均值 ± 标准差"。
2. **best_epoch=0 是个反常信号**:验证 AUC 在第 0 轮就到顶、之后 9 轮再没超过。注意第 0 轮内已发生全部 5 次 SVD 更新(1103 批/epoch ÷ 200 步间隔)——也就是说**"1 轮训练 + 5 次谱更新"的组合已经是最佳状态**,继续训练反而变差。可能的原因:reader 漂移(辅助模块继续学,把候选表示带偏)、R 与候选构建器的共适应不稳、或验证指标本身噪声大。

**影响**:0.9001 是一次抽样的"epoch-0 状态"分数;在做多 seed 之前,建议先查清"epoch 1+ 为什么不涨",否则多 seed 可能白烧算力。

## 第 3 章 C 类:规格要求但缺失(10 条)

> 这些缺失**不改变 PRSS 当前的分数**,但决定"0.9001 能不能归因于 PRSS 的谱机制"。是论文主张的命门。

---

### C1. 基线组缺失(random / PCA / 直接6学习的dk投影 / ridge reader / Jacobian)

**规格要求**(§21.5、§30.3):至少与 5 类对照比较;其中"full PRSS 必须优于同 lift + 直接学习的 d→k 投影"是硬性验收标准(§30.3)。

**代码现实**:当前训练器只有 `--mode vanilla` 一个对照。旧实现(`PRSS-method_old_021746/prss/ablations.py`)有 7 个具名变体,但基于旧训练器,不能直接引用:

| 旧实现变体 | 含义 |
|:---|:---|
| `fixed_random` | R 固定为随机正交矩阵 |
| `pca` | R 由候选状态的协方差(方差方向)决定,而非 reader Gram |
| `direct` | R 注册为可学习参数,由任务损失直接学 |
| `linear_reader_svd` | context→B 为线性映射 + Gram SVD |
| `no_nonlinear_lift` | 线性 lift + Gram SVD |
| `neural_svd_no_spec` | 去掉谱尾损失 |
| `full` | 完整 PRSS |

**白话讲解**:论文的主张是"**我的选方向方法(SVD 谱选)比别人好**"。要证明,必须让几种选法在同一起跑线比:
- **随机正交选**(随机选择):下限,说明"选"本身有价值;
- **PCA 选**(按历史数据方差选):说明"面向未来选"胜过"面向过去选";
- **直接学习投影**(让网络自己学):最关键——若它也能拿 0.90,说明 SVD 机制没有额外贡献,方法主张破产。

**影响**:决定"0.9001 是否算谱机制的功劳"。**优先级最高。**

---

### C2. energy@k 没有与 random/PCA 的覆盖对比

**规格要求**(§30.2):"energy@k 必须**明显高于** random/PCA 的 predictive energy coverage"。

**代码现实**:`spectral.py` 的 `snapshot()` 已经计算了 energy@k/4、k/2、k、full(当前值为 1.0),但**没有实现"随机 R 和 PCA-R 在同一个 Gram 上能覆盖多少能量"的对照计算**。

energy@k=1.0 只说明"前 172 维覆盖了几乎所有需求"。但如果不和随机/PCA 比,无法知道这是"选法的功劳"还是"需求本来就集中在**任意** 172 维里"(那样谁都行)。打个比方:考了 95 分,但不知道全班平均是 94 分还是 60 分。

**影响**:随 C1 一起补;

---

### C3. 没有 parameter-matched(等参数)对照

**规格要求**(§30.5):"baseline 要做 parameter-matched"。

**代码现实**:PRSS 的主前向路径比 vanilla 多了候选构建器 φ(约几十万参数);vanilla_matched 没有任何等参数补偿。

**白话讲解**:PRSS 多带了一个 φ 网络。如果直接比,赢了也可能被说"你只是参数多"。公平做法:给 vanilla 也加一个**等参数量的组件**(如同宽度的 MLP 投影),让双方"智力硬件"一致,再比方法。

**影响**:影响归因;随 C1 一起补。

---

### C4. PRSS 版 history-mixing 诊断未实现

**规格要求**(§21.6):这是"验证理论主张**最重要的机制实验之一**"——构造"局部预测相近、但在不同 sibling/context 下未来结果不同"的历史对,检查 PRSS 是否比普通 k 维瓶颈更能区分它们。

**代码现实**:`tgn/diagnostics/collision_analysis.py` 做的是**冻结 TGN 的 (h,C) 撞车分析**(动机证据:"普通 TGN 会把不同历史压成一样"),**不是**"PRSS 装上之后撞车减少"的机制检验。后者在任何地方都没有实现。

**白话讲解**:方法的招牌主张是"减少历史混叠"(第 1 章 A 类之外的理论动机)。检验方法很直白:找出"看起来一样、命运不同"的历史对(术语:混叠对),看 PRSS 的状态能否把它们区分开。缺了这个,方法的核心卖点没有直接证据。

**影响**:**优先级最高**,与 C1 并列。

---

### C5. 官方母本训练器没有消融开关(A–H)

**规格要求**(§22):至少 8 项消融,逻辑链:A(随机 R)→ B(PCA)→ C(直学投影)→ D/E(有无非线性 lift)→ F(去 L_spec)→ G(完整)→ H(Jacobian 版)。结论判据:"若 full PRSS 的提升只来自更大的 lift,而不是 spectral mechanism,则论文主张不成立。"

**代码现实**:当前训练器无任何 ablation 开关;旧实现有 7 个变体(见 C1 表),但基于旧训练器。

**白话讲解**:消融 = 逐件拆零件。这套 8 项设计像一条证据链:如果 full 输给 C(直学投影),说明 SVD 没用;如果 full 只赢 A/B,说明只是"选得比瞎选好",不算"谱机制"的胜利;只有 full 在 E→G 之间显示出"lift 之外、SVD+L_spec 带来的增量",方法才立得住。

**影响**:决定方法主张;实现成本中等(在训练器加 `--ablation` 开关即可,旧实现可移植)。

---

### C6. λ_spec 敏感性实验未执行

**规格要求**(§23):对 λ_spec ∈ {0, 0.01, 0.1, 0.5, 1.0} 做小范围敏感性。

**代码现实**:当前只有 λ_spec=0.1 的一次运行;旧实现有 `run_lambda_sensitivity_autodl.sh` 脚本,但未在新训练器执行。

**白话讲解**:谱尾损失是"逼需求集中"的力度旋钮。0.1 只是规格给的起点,未必最优。**当前 0.9001 可能被低估**(别的档位分数更高)。

**影响**:直接影响最终分数(见上一轮讨论);执行成本低,直接跑。

---

### C7. Jacobian-SVD 备用方案未实现

**规格要求**(§20):当"线性读取"诊断失败(structured 远差于 unrestricted MLP)时,切换为 Jacobian 版:对非线性 reader 在 h 处求**雅可比矩阵**(局部一阶近似),用它建 Gram。规格明确说"只有当诊断失败才切换"。

**代码现实**:完全未实现。

**白话讲解**:Jacobian = 非线性函数在某一点的"局部线性斜率"。我们的方法假设"未来读取可以用一个矩阵 B 完成"(线性假设);万一现实不是线性,备胎是:在当前位置取斜率当近似矩阵。代价:斜率是局部的、计算贵、方差大、理论解释变弱。规格的策略是"先诊断,再决定"——而诊断本身(A10 的 structured-vs-unrestricted 对比)还没有系统性结论,所以暂不实现是符合规格的。

**影响**:暂不阻塞;先做 §21.1 诊断评估再决定。

### C8. 多数据集(Phase 4:UCI / Enron)未做

**规格要求**(§29 Phase 4):Wikipedia 之后应在 UCI/Enron 上做初步实验与多 seed。

**代码现实**:数据文件不在工作区;只有训练入口支持 `--data NAME`。

**白话讲解**:单数据集 = 单案例。泛化性主张需要第二个、第三个数据集背书。UCI/Enron 也是官方 TGN 支持的格式,接入成本低,缺的只是数据与算力。

**影响**:影响论文说服力,不影响当前分数。

### C9. 理论四项空白未推进

**规格要求**(§27):明确列出四件"还没证明、论文不能过度声称"的事。

1. **有限样本一致性**:数据越多,估计的 B̂、Ĝ 是否收敛到真值?top-k 子空间恢复误差多大?——"抽样统计靠不靠谱"的数学保证。工具:Davis–Kahan 定理(矩阵受扰动后特征空间漂移的经典界限,类似"天平受小扰动,读数误差有上限")。
2. **identifiability(gauge 自由度)**:Φ 和 B 可以互相"打滑"(Φ 放大、B 缩小,乘积不变)——说明我们**只能声称 rowspace(R) 和预测行为是稳定的,不能声称具体坐标有含义**。这是论文措辞问题,不是 bug。
3. **support gap**:见过的上下文 ≠ 所有合法上下文。"训练中见过的未来场景"永远只是真实未来场景的子集;推广到没见过的新场景需要额外验证(rolling split、OOD 时间窗)。
4. **rank-k 误差到 task risk 的上界**:每层丢掉的谱尾能量,经过非线性递归**放大**多少,最终变成预测误差?需要 Lipschitz 光滑假设(输出对输入的敏感度有上限)才能给全局保证。

**影响**:理论章节的边界声明;不是编码 blocker,但决定论文哪些话能说、哪些不能说。

---

### C10. 合成树识别测试(Phase 2)未迁移到当前包

**规格要求**(§29 Phase 2):"这个 synthetic test 通过以前,不要直接跑 TGN 大实验"——构造已知答案的玩具问题 `D,E→A→Y`(D 的某些方向单独无用、与 E 交互后才决定 Y),验证 PRSS 恢复真实预测子空间。

**代码现实**:测试只在旧实现(`PRSS-method_old_021746/experiments/synthetic_tree.py`)存在并通过:恢复出的最大主角度 **0.00256 rad**(≈0.15°,说明找的方向与真方向几乎重合)、真子空间覆盖率 **0.9999968**。当前包(`PRSS-method/tests/`)里没有。

这是"已知答案的模拟考":题目里预埋了"哪几个方向才是真正重要的",看算法能不能把它们找出来。它在数学层面验证"谱选方向"逻辑正确;当前包的测试只验证了实现正确性(SVD 等价、初始化一致、隔离性),**没有验证方法本身在可控条件下的正确性**。

**影响**:回归保障缺失;迁移成本低(旧文件可移植),建议与 C1 一起做。
