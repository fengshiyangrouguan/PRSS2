```rationale
The current solver uses a fixed-order list scheduling heuristic (process jobs in input order, ops sequentially within job, set start = max(prev_op_finish, machine_avail)). This is basic but suboptimal: it fails to prioritize high-impact operations/jobs (e.g. long ops or those on bottleneck machines), leading to poor idle-time avoidance on larger/variable instances (see low scores on tai100_20.txt ~0.065 and tai50_20.txt ~0.07). Gap to best-known (0.027) is largest in high-variance test suites (tai instances with n=20–50). Fix: pre_process guidance for a simple dispatching rule (LPT job ordering + earliest-start list scheduling) that solver can implement directly without extra libs. This targets observed failure patterns (suboptimal job permutation, excessive idle on shared machines) without complexity that would introduce runtime breaks. Expected uplift: +0.02–0.03 mean score via better makespan estimates on most test cases.
```
